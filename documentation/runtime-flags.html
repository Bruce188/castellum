Runtime Flags & Native Dependencies

Castellum runtime requirements for pcap4j passive discovery: JVM native-access flags, the CAP_NET_RAW Linux capability, the libpcap native library, the resolved Debian-12 distroless base, the Linux-only v1 contract, the setcap alternative, the security-critical environment variables, and the DISCOVERY_* passive-discovery tunables.

Section: operations · Audience: operators & sysadmins

[NOTE] TODO (feature 9): wire the JVM flags into the ENTRYPOINT java line. The distroless base is resolved — see §4.

This document is the single source of truth for the pcap4j runtime requirements introduced in feature 4 (feat/passive-discovery). Feature 9 (feat/security-hardening-and-supply-chain) will read from this file when wiring the production Dockerfile.

1. JVM flags

The pcap4j 1.8.x library uses JNA to call into the native libpcap.so library. JNA reflectively accesses internals of sun.nio.ch and triggers JDK 21's restricted-native-access guard. Two JVM flags are required:

  • --enable-native-access=ALL-UNNAMED
  • --add-opens java.base/sun.nio.ch=ALL-UNNAMED

These flags are wired in Maven Surefire (backend/pom.xml → <build><plugins> → maven-surefire-plugin → <argLine>) so tests run with the same flag set as production.

When feature 9 lands the production Dockerfile, the ENTRYPOINT java line MUST include both flags. Example:

ENTRYPOINT ["java", \
  "--enable-native-access=ALL-UNNAMED", \
  "--add-opens=java.base/sun.nio.ch=ALL-UNNAMED", \
  "-jar", "/app/backend.jar"]

2. Linux capability

The PCAP source (PcapSniffer) opens raw sockets via libpcap. Raw-socket open requires the CAP_NET_RAW Linux capability.

The production container MUST run with CAP_NET_RAW and all other capabilities dropped. Example Docker run:

docker run --cap-drop=ALL --cap-add=NET_RAW castellum:latest

Equivalent Kubernetes securityContext:

securityContext:
  capabilities:
    drop: ["ALL"]
    add: ["NET_RAW"]

The ARP, MDNS, CONN_TABLE, and GATEWAY sources do NOT require CAP_NET_RAW. ARP reads /proc/net/arp, CONN_TABLE reads /proc/net/{tcp,tcp6,udp,udp6}, and GATEWAY reads /proc/net/route (filesystem only). MDNS uses the JVM's standard multicast socket.

3. Native library

libpcap.so (Linux package: libpcap0.8, version >= 1.0.0). NOT a Maven dependency — provided by the host OS or container layer.

On Debian/Ubuntu: apt-get install libpcap0.8.

4. Distroless base (resolved)

[NOTE] Resolved. The production image is built on the Debian-12 distroless variant, which ships libpcap, so the PCAP source works in containerized deployments. The earlier "pure-distroless lacks libpcap" caveat no longer applies.

The repository Dockerfile pins the final stage to:

FROM gcr.io/distroless/java21-debian12:${DISTROLESS_VARIANT}

with ARG DISTROLESS_VARIANT=nonroot. Unlike the pure gcr.io/distroless/java21 image, the java21-debian12 variant is built on Debian 12 (bookworm) and includes the libpcap shared library, so the pcap4j → JNA → libpcap.so path resolves at runtime without an additional package-install layer. No apt-get install libpcap0.8 step is required, and the choice does not sacrifice the distroless minimal-attack-surface posture (no shell, no package manager) — the Debian-12 distroless variant retains those properties.

This is the option originally tracked as "(a) drop pure distroless for the Debian-12 distroless base." It is now the committed decision; there is no separate discovery image and no host-deployment-only degradation. See documentation/supply-chain.html, which cites the same gcr.io/distroless/java21-debian12:nonroot base.

5. Linux-only contract for v1

/proc/net/arp does not exist on Windows or macOS. The ArpCacheReader returns an empty list when the file is absent (no exception). The same contract covers the other proc-backed sources: ConnTableReader (/proc/net/{tcp,tcp6,udp,udp6}) and GatewayProbe (/proc/net/route) also degrade to an empty list when their files are absent — never an exception. Future ports could read:

  • Windows: GetIpNetTable via JNA.
  • macOS: /Library/Preferences/SystemConfiguration/... plus arp -an parsing (sysctl-based).

Both ports are out of scope for v1. README documents the Linux-only contract operationally.

6. setcap alternative for non-Docker deployments

For systemd or bare-metal deployments where Docker capability dropping is not available, setcap on a Java wrapper script grants CAP_NET_RAW without root:

sudo setcap cap_net_raw+eip /usr/local/bin/castellum-launcher

Caveat: setcap on the JDK binary itself is brittle — java binary updates wipe the capability. Prefer setcap on a wrapper script that exec's the real java.

7. Environment variables

Environment-driven configuration. The backend resolves these via Spring's standard Environment bean.

CASTELLUM_INTEGRATION_KEY

AES-256 key (32 bytes, hex- or base64-encoded depending on operator preference; the cipher reads the raw byte length) used to encrypt TAXII / MISP credentials at rest in the integration_config table. Required when the threat-intel-push integrations (TAXII, MISP) are configured. Read by AesGcmCipher at boot — startup fails fast with a clear error if the variable is missing while at least one integration_config row exists. Generation:

openssl rand -hex 32

Rotation is non-trivial: changing the key requires re-encrypting every row in integration_config with the new key. The current implementation does not include a rotation helper; rotation today is "truncate the table, re-enter credentials in the UI under the new key." A future feature will add a ROTATION_KEY env that runs a one-shot re-encrypt on boot.

CASTELLUM_SECURITY_JWT_SECRET

HMAC-SHA256 signing key for issued JWTs. Maps to property castellum.security.jwt.secret. Read by JwtService at boot — startup fails with an explicit error ("Refusing to start with default JWT secret placeholder; set CASTELLUM_SECURITY_JWT_SECRET") if the default placeholder is still in use outside the test Spring profile. Must be ≥ 32 bytes. Generate with openssl rand -hex 32. Rotation invalidates every outstanding token instantly; combine with token_version bump (via disable or password-change) for per-user invalidation.

CASTELLUM_ADMIN_USERNAME / CASTELLUM_ADMIN_PASSWORD_HASH

Required to seed the admin account. BootstrapAdminInitializer runs at ApplicationReadyEvent and performs an idempotent upsert: if the user does not exist it is created; if it exists and the stored BCrypt hash differs from the env var, the hash is updated and an ADMIN_HASH_ROTATE audit event is emitted. If either variable is absent or blank, the bootstrap step is skipped with a warning. The operator must supply a pre-computed BCrypt strength-12 hash — the application never generates or logs a plaintext password. Equivalent variables exist for the viewer account: CASTELLUM_VIEWER_USERNAME / CASTELLUM_VIEWER_PASSWORD_HASH.

First-login rotation: mustChangePassword in the login response is true when user.lastLoginAt == null and the username matches a bootstrap principal — computed live in AuthController on each login, not stored as a database column.

Generate a BCrypt strength-12 hash: htpasswd -bnBC 12 "" "<password>" | tr -d ':\n'

DISCOVERY_* (passive discovery)

Tunables for the passive-discovery sweep. Each variable maps to a property under castellum.discovery in application.yml; the listed default applies when the variable is unset.

VariableDefaultEffect
DISCOVERY_DURATION_SECONDS30Declared in application.yml (castellum.discovery.default-duration-seconds) but currently not consumed by any code path — the capture-window default for time-bounded sources (mDNS, PCAP) is a fixed 30 s in PassiveDiscoveryController. Override the window per request via the durationSeconds field instead.
DISCOVERY_PASSIVE_SWEEP_CRON0 0 */6 * * *Spring cron expression (UTC) for the scheduled passive sweep — every 6 hours by default. The scheduled sweep runs only the local-read sources: ARP, CONN_TABLE, GATEWAY.
DISCOVERY_ARP_PATH/proc/net/arpARP cache file read by ArpCacheReader.
DISCOVERY_MDNS_SERVICE_TYPES5 service typesComma-separated mDNS service types queried by MdnsProbe. Default: _workstation._tcp.local., _http._tcp.local., _ssh._tcp.local., _smb._tcp.local., _printer._tcp.local.

DISCOVERY_PCAP_MAX_CAPTURED_NEIGHBORS50000Bound on the in-memory capture queue per capture window. Once reached, the sniffer stops offering neighbors, logs a single truncation WARN, and drops all further frames in the window.
DISCOVERY_LLDP_ENABLEDfalseOpt-in toggle for the LLDP source (live capture + IEEE 802.1AB TLV decoder). A sweep that requests LLDP while the flag is off soft-skips the source (logged, no error). DISCOVERY_LLDP_MAX_CAPTURED_FRAMES1000Bound on the LLDP frames decoded per capture window. Once reached, a single truncation WARN is logged and all further frames in the window are dropped.

When enabled, the sweep request must name an interface explicitly and the process needs CAP_NET_RAW — see operations.html §13.
DISCOVERY_CDP_MAX_CAPTURED_FRAMES1000Bound on the CDP frames decoded per capture window. Once reached, a single truncation WARN is logged and all further frames in the window are dropped.
DISCOVERY_CONN_TABLE_ENABLEDtrueOpt-out for connection-table discovery (ConnTableReader). Set to false to stop recording the remote peers of the host's own connections.
DISCOVERY_CONN_TABLE_MAX_REMOTES512Per-read cap on distinct remote peers collected from the connection tables (first-N in file-read order, applied after dedupe). A WARN is logged when the cap truncates.
DISCOVERY_BPF_FILTERip or ip6 or arplibpcap BPF filter applied by PcapSniffer. Narrow it to discard irrelevant traffic before it reaches the JVM.
DISCOVERY_PUBLIC_DEVICE_PRUNE_ENABLEDtrueToggle for the PUBLIC-device retention job. When off, the scheduled tick is a no-op and stale external peers are kept forever.
DISCOVERY_PUBLIC_DEVICE_PRUNE_CRON0 30 3 * * *Spring cron expression (UTC) for the retention job — daily at 03:30 by default. Set to - to disable scheduling entirely.
DISCOVERY_PUBLIC_DEVICE_TTLP14DISO-8601 duration, strictly parsed, minimum PT1H (both enforced at boot — a value that is not strict ISO-8601, such as a bare number like 31536000 or simple-style 30d, is rejected at startup, as is any duration below PT1H). A device is pruned only when its discoveryScope is PUBLIC, its lastSeen is older than this TTL, its discovery source is a passive one (ARP, mDNS, PCAP, LLDP, CDP, CONN_TABLE, GATEWAY), and it carries no scan attribution. Other scopes are never touched.

CONN_TABLE is on by default. ConnTableReader parses /proc/net/{tcp,tcp6,udp,udp6} and emits one MAC-less neighbor per unique remote endpoint — TCP rows in state ESTABLISHED, UDP rows with a non-zero remote (connected sockets). It is a pure file read: no CAP_NET_RAW, no wire traffic. This is the source that surfaces off-network (PUBLIC-scope) peers on any host with outbound connections. Because remote peers choose to connect, they would otherwise control inventory growth on a busy public-facing host — DISCOVERY_CONN_TABLE_MAX_REMOTES caps each read. Missing proc files (Windows/macOS, locked-down containers) degrade to an empty list, never an exception. Opt out with DISCOVERY_CONN_TABLE_ENABLED=false.

GATEWAY has no toggle. GatewayProbe reads the Gateway column of the default-route row in /proc/net/route and emits at most one MAC-less neighbor, so the router itself always lands in the inventory. A missing or malformed route table yields an empty result — never an exception.

PCAP is off by default — deliberately. Beyond ARP frames, the sniffer now decodes the IPv4/IPv6 source and destination address of every captured packet into a MAC-less neighbor (filtering non-host addresses: 255.255.255.255, subnet-directed .255 broadcast, and multicast), so device creation scales with packet rate, not host count. The PUBLIC-device retention job (below) now bounds cumulative inventory growth, but PCAP stays opt-in because a capture also requires an explicit interface name and CAP_NET_RAW — neither of which a default deployment is guaranteed to have. DISCOVERY_PCAP_MAX_CAPTURED_NEIGHBORS bounds a single capture window's memory.

LLDP is off by default and shares PCAP's prerequisites. The LLDP source (LldpCapture / LldpDecoder) opens its own libpcap handle in promiscuous mode (LLDP frames target the multicast group 01:80:c2:00:00:0e) with the fixed BPF filter ether proto 0x88cc, so it needs CAP_NET_RAW and an explicit interface name — a sweep that requests LLDP with a blank interface is rejected with LLDP source requires interface name. Neighbors that advertise no management address are persisted under a synthetic mac:… placeholder key in the ip_address column and render as "no IP" throughout the UI; the full operational story (what gets decoded, the frame cap, placeholder semantics, self-healing to a real IP, scope/graph/export behaviour) is in operations.html §13.

CDP follows the same pattern. The CDP source (CdpCapture / CdpDecoder) surfaces Cisco(-compatible) infrastructure the same way: its own libpcap handle in promiscuous mode (CDP frames target the multicast group 01:00:0c:cc:cc:cc) with the fixed BPF filter ether dst 01:00:0c:cc:cc:cc — CDP rides 802.3/SNAP frames, so there is no ethertype to match on — and the same CAP_NET_RAW and explicit-interface prerequisites: a sweep that requests CDP with a blank interface is rejected with CDP source requires interface name. The destination-MAC filter also admits the sibling Cisco control protocols that share the multicast group (VTP, DTP, PAgP, UDLD); the decoder's mandatory SNAP protocol-ID gate (0x2000) rejects them, so they never become device rows. Neighbors without an advertised address reuse the same mac:… placeholder mechanics as LLDP. Full details in operations.html §13.

Stale PUBLIC devices are pruned on a TTL. A daily retention job (DevicePruneScheduler, 03:30 UTC by default) hard-deletes devices whose discoveryScope is PUBLIC and whose lastSeen is older than DISCOVERY_PUBLIC_DEVICE_TTL (14 days by default). Only passively-observed peers are eligible: the device's discovery source must be one of ARP, mDNS, PCAP, LLDP, CDP, CONN_TABLE, or GATEWAY. Devices carrying scan attribution, devices sourced from NMAP_SCAN or OT_PROBE (their lastSeen means "last scanned", not "the fleet stopped talking to them"), and manually created devices (no discovery source) are never pruned. The semantics are coherent with CONN_TABLE: any external peer the host still talks to is re-observed every sweep (6 h by default) and its lastSeen refreshed, so only peers genuinely absent from the connection tables age out. A run that prunes at least one device records a single DEVICE_PRUNE audit event carrying the count, the effective cutoff, the TTL, and a capped (50) identity sample (id, IP address, origin host, lastSeen), then evicts the risk caches once the delete has committed; an empty run is a true no-op — no audit row, no cache eviction. The count comes from the DELETE itself and is authoritative; the sample is a best-effort pre-delete snapshot of the rows eligible at sweep start — a device refreshed between the sample and the delete may be named in the sample yet survive, so the sample size can fall below or above the count. Service rows of pruned devices are removed by the database's ON DELETE CASCADE.

Keeping a host out of the prune, and the TTL floor. To keep a specific external host forever, re-scope it away from PUBLIC: the IP-classified upsert paths set discoveryScope on first insert only and never overwrite it on update, so re-scoping a conn-table peer off PUBLIC protects it from pruning. (The scope-explicit Docker ingest path is last-writer-wins, but it stamps DOCKER_BRIDGE, not PUBLIC.) Alternatively, raise the TTL or disable the job via the variables above. The TTL is validated at boot: the value must be a strict ISO-8601 duration — anything else (a bare number such as 31536000, or simple-style 30d) is rejected at startup, and a valid ISO-8601 duration below the PT1H floor is rejected too — failing fast instead of mass-deleting the PUBLIC inventory at the next tick.

MAC-less rows from CONN_TABLE, GATEWAY, and PCAP are deduplicated MAC-primary in PassiveDiscoveryService: when a MAC-bearing row (typically ARP) shares the IP, the MAC-less row is dropped and the surviving row backfills hostname/iface from it when those are null. This is why the gateway does not appear twice when it is also in the ARP cache.
